## Interpretation notes / 解读

- `enum_count` / `template_arg_count` are constexpr table reads; ~1 ns/op in
  Release is the loop-bound measurement floor, not meaningful per-op cost.
- `for_each_field(obj, values)` constructs a fresh `BenchDerived` object per
  iteration (including a `std::string`), so the Debug 555 ns/op includes
  per-iteration construction; Release 10.12 ns/op reflects the tuned path.
- Empty tables (`enum_count<Empty>` == 0, `for_each_enum<Empty>`,
  `template_arg_count<int>`) exercise the "unregistered / empty" safety path:
  no iteration happens, cost is just the call + loop overhead.
- Re-run locally before reporting throughput; `scripts/run_bench.ps1` reproduces
  these captures.
